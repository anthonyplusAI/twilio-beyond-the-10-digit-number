# Deploying the webinar demo

The presenter site, customer banking view, API, and ConversationRelay WebSocket share one Node server on port 8080. Azure Container Apps gives that server one public HTTPS hostname and supports WebSocket upgrades. This demo's voice URL is `wss://twilio-branded-comms.jollymushroom-29e673c9.centralus.azurecontainerapps.io/voice-relay`. [Azure ingress](https://learn.microsoft.com/en-us/azure/container-apps/ingress-overview) · [Twilio ConversationRelay onboarding](https://www.twilio.com/docs/voice/conversationrelay/onboarding)

## Deploy or redeploy

1. The [one-time Azure and GitHub setup](INFRA_SETUP.md) has been completed for this repo. If rebuilding the infrastructure, configure external ingress on port 8080, a private `PRESENTER_PASSWORD` secret, and `PUBLIC_BASE_URL=https://<app-fqdn>` first.
2. Push to `main`, or run `gh workflow run deploy.yml --ref main`. Follow the run with `gh run watch --exit-status` or in GitHub Actions.
3. Confirm `https://<app-fqdn>/healthz` returns HTTP 200. Open `https://<app-fqdn>/bank` in the audience window. Open `https://<app-fqdn>/presenter` in a separate, private window and enter the presenter password there. The password is saved in local `.env` and an Azure secret; it is not printed by the hosted server.
4. Confirm the presenter view shows the SMS, RCS, and voice features you plan to use as ready. If a feature is missing, set its [live demo values](INFRA_SETUP.md#live-demo-settings) on the Container App before rehearsing.

The Container App hostname also serves `/rcs-sender-logo.png`, `/rcs-sender-banner.png`, and `/rcs-case-update-card.png` as stable public HTTPS assets for the RCS test setup. Deploy the new case card before running `npm run create:rcs-template`; the helper checks that the public image is reachable. An RCS Sender still needs its normal Twilio onboarding and accepted test device. [Twilio RCS onboarding](https://www.twilio.com/docs/rcs/onboarding) · [RCS card media](https://www.twilio.com/docs/content/twiliocard)

## How releases work

The [CI workflow](CICD.md) runs `npm ci`, syntax checks, and tests. Only a passing `Validate` job allows the deploy workflow to build a Node 22.23.4 image, push it to Azure Container Registry with a tag combining the full commit SHA, GitHub run ID, and run attempt, update the Container App, wait for the new revision to be ready, and check `/healthz`, `/bank`, `/bank?case=1`, and the case-card PNG. Each deployment attempt gets a distinct image tag, including reruns of the same commit. GitHub signs in to Azure through OIDC; app credentials stay in Container Apps secrets and are never copied into the image or GitHub Actions. [Azure GitHub Actions](https://learn.microsoft.com/en-us/azure/container-apps/github-actions) · [Azure revisions](https://learn.microsoft.com/en-us/azure/container-apps/revisions-manage) · [Azure OIDC](https://learn.microsoft.com/en-us/azure/developer/github/connect-from-azure-openid-connect) · [Container Apps secrets](https://learn.microsoft.com/en-us/azure/container-apps/manage-secrets)

The deploy workflow changes only the image and replica limits. It leaves runtime environment variables and secrets alone. To change a Twilio SID, number, API key, presenter password, or public URL, update the Container App configuration separately. Avoid deploying during the webinar: story state, presenter sessions, and live call history are in memory, so a new revision or restart resets them. One warm replica avoids scale-to-zero delay; Azure may temporarily run an extra replica during maintenance. [Azure scaling](https://learn.microsoft.com/en-us/azure/container-apps/scale-app)

## Troubleshooting

- **Preflight fails:** set the three GitHub variables and three OIDC identity values listed in [INFRA_SETUP.md](INFRA_SETUP.md). The workflow accepts only `main`.
- **Image push succeeds, rollout says `UNAUTHORIZED`:** confirm the Container App's managed identity has `AcrPull` on the registry and `az containerapp registry set` points to that identity. [Microsoft image-pull guide](https://learn.microsoft.com/en-us/azure/container-apps/managed-identity-image-pull)
- **Health smoke fails:** check `PUBLIC_BASE_URL`, `PRESENTER_PASSWORD`, port 8080, and revision logs with `az containerapp logs show --name <app> --resource-group <group> --follow`.
- **The live SMS button stays disabled:** first complete the branded call and mark the charge unrecognized. Then check `TWILIO_SMS_FROM`, `TWILIO_MESSAGING_SERVICE_SID`, the shared Twilio credentials and fixed test destination, and that the SMS number is in the Messaging Service's sender pool. The verified toll-free number currently lists marketing; update its registered use case before production fraud-alert traffic. [Twilio toll-free verification](https://www.twilio.com/docs/messaging/compliance/toll-free/console-onboarding) · [Twilio sender selection](https://www.twilio.com/docs/messaging/services)
- **The live RCS button stays disabled:** complete the call and SMS comparison first. Check the accepted RCS tester, sender in the same Messaging Service, and `TWILIO_RCS_CASE_CONTENT_SID`. The old `TWILIO_RCS_CONTENT_SID` belongs to the fraud-question template and is ignored by this story. Create a new case-update template after the image is deployed. [Twilio RCS testing](https://www.twilio.com/docs/rcs/onboarding) · [Content Template](https://www.twilio.com/docs/content/content-api-resources)
- **The live call button stays disabled:** check the Twilio account, approved voice number, destination number, Auth Token, and OpenAI key. The WebSocket URL is derived from `PUBLIC_BASE_URL` unless explicitly overridden. Twilio also requires ConversationRelay onboarding. [Twilio onboarding](https://www.twilio.com/docs/voice/conversationrelay/onboarding)
